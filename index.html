    How it works

    The skill runs in your coding agent after a UI change. It reads the code first, then measures the page, then checks each finding once more before it reports.

    1. 1

      Find the change

      It reads the diff you name: a PR, a branch, a commit or the uncommitted work. With no UI file in the diff, it stops.

    2. 2

      Read the repo’s rules

      Your repo’s UI rules and components win over the catalog. A fix names your dialog helper, your tokens, your async button.

    3. 3

      Map the surfaces

      Each changed file maps to the views a user sees, tagged with kinds such as write, list or overlay, and the states to open.

    4. 4

      Check, then measure

      It runs each rule that fits a surface: in code first, then in the browser at phone and desktop widths, in each theme.

    5. 5

      Verify and report

      A browser finding must repeat after a reload. Each one ships as surface, rule, evidence and fix, most severe first.

    Measured in every state

    Most defects sit in a state the author did not open. The skill opens each one, takes a snapshot, and compares the boxes. Each state below opens a demo.

    • At rest
    • Hover
    • Keyboard focus
    • Selected next to hovered
    • Pending
    • After a reload
    • Light and dark
    • Phone width

    The rule catalog

    Each rule has a reason, a check in code, a check in the browser and a fix. This list is generated from the skill’s rules.md.

    Get started

    The skill is a folder with a SKILL.md, the rule catalog and the measurement script. Any agent that reads skills can load it.

    1. Clone the repo

      git clone https://github.com/ktmud/ux-quality-check-skill

    2. Add the skill folder

      Copy it into your agent’s skills folder. This example uses ~/.claude/skills/.

      cp -R ux-quality-check-skill/skills/ux-quality-check ~/.claude/skills/

    3. Ask for a check

      After a UI change, ask in your own words. With a dev server and a browser tool, it also measures the page.

      • “Check the UX of this change.”
      • “UX review this diff.”
      • “Look for UX issues on the settings page.”
